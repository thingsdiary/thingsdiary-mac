# Лаборатория изменения ширины сайдбара

Лаборатория сравнивает девять способов сохранить рабочий интерфейс thingsdiary при сужении окна и сайдбара. Ширина окна и положение разделителя настраиваются отдельно.

Запуск из этой папки:

```sh
swift run
```

Для приложения лучше объединить несколько решений:

1. Растягивать содержимое прокрутки и строки по доступной ширине сайдбара.
2. Обрезать конец текста до того, как иконки или выделение выйдут за границы колонки.
3. Держать ширину колонки в проверенном диапазоне 200–300 пт.
4. Если окно становится слишком узким, скрывать сайдбар. Вернуть его можно кнопкой в панели инструментов или командой меню «Вид».

Главная ошибка возникает из-за противоречивых ограничений. `ContentView` разрешает окно шириной 520 пт, а `EntriesView` требует не меньше 900 пт. SwiftUI центрирует слой шириной 900 пт внутри узкого окна и обрезает его с обеих сторон. На первом снимке строки сайдбара также не помещаются в родительскую колонку. Вертикальный `ScrollView` не сжимает собственное содержимое так же надёжно, как системный `List` со стилем sidebar.

Исправление состоит из двух частей:

- Убрать локальный `minWidth: 900`. Если приложение не должно работать в узких окнах, такой минимум нужно задавать на уровне окна.
- В адаптивном варианте скрывать одну колонку на малой ширине, не заменять структуру split view и закрывать сайдбар до того, как он перестанет работать.
- Растягивать внутренний стек сайдбара по ширине и обрезать подписи после одной строки.

Рекомендации Apple, использованные в лаборатории:

- [Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars)
- [Split views](https://developer.apple.com/design/human-interface-guidelines/split-views)
- [Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars)
- [NavigationSplitView](https://developer.apple.com/documentation/swiftui/navigationsplitview)
